BABBLE BRIDGE 1.0.0 — WINDOWS x64

PREREQUISITE
Install the Microsoft Visual C++ v14 Redistributable (x64) from Microsoft:
https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist
Setup does not download this prerequisite. The app includes its separate .NET
runtime and accompanying notices.

GET STARTED
1. Run Babble-Bridge-Setup.exe. Setup installs for your Windows account and
   offers an optional desktop shortcut. For a portable build, extract the
   entire folder and keep its runtime, Assets, licenses and notice files.
2. Close the separate VRCFaceTracking app and open Babble Bridge.
3. Import your VRCFaceTracking module ZIP. Modules are obtained separately;
   none is included or downloaded automatically. You can keep multiple
   imported modules and select the one you want to use.
4. Start the matching headset runtime or desktop tracking app. Enable the
   tracking permissions and forwarding settings it requires (see below).
5. Enable OSC in VRChat and select an avatar with face tracking. OSCQuery
   discovers a local VRChat instance and its avatar parameters automatically.
   Reselect the avatar if VRChat was already running and needs a refresh.

The selected module and its connection settings are remembered. Switching
modules restarts the tracking worker and applies the appropriate input.
Only one module is active at a time. Avoid running another tracking app that
uses the same input or VRChat output ports.

MODULE CONNECTIONS
Babble Headset Runtime
  Import the Baballonia VRCFaceTracking module and select its headset-runtime
  connection. Start Babble Frame Runtime on the headset. The headset and PC
  must be able to reach each other on the network. BFR Link uses UDP 6767.
  If Windows asks about network access, allow it on your trusted network as
  appropriate. This app does not install the headset runtime or edit firewall
  rules. If discovery is blocked, try the runtime's PC IP fallback.
  Module: https://github.com/Project-Babble/Baballonia
  Runtime: https://github.com/Project-Babble/Babble-Frame-Runtime

Baballonia desktop
  Import the Baballonia module and select its desktop connection. Keep the
  desktop Baballonia app running with VRCFaceTracking output enabled toward
  127.0.0.1:8888. Desktop input uses UDP 8888, including both eye and face input.
  https://github.com/Project-Babble/Baballonia

Virtual Desktop
  Import the VirtualDesktop.VRCFaceTracking module. Run Virtual Desktop
  Streamer 1.30 or later and enable eye/face tracking forwarding and the
  headset's required permissions. This module reads local shared memory;
  it does not use a tracking-input UDP port.
  https://github.com/guygodin/VirtualDesktop.VRCFaceTracking

Steam Link
  Import the Ykeara LinkFT module. In Steam Link advanced settings, enable OSC,
  share the available eye/face tracking data, and set OSC Output Port to 9015.
  This module receives local UDP on 127.0.0.1:9015.
  https://github.com/ykeara/LinkFT

Available expressions depend on your headset, module and avatar. The current
Virtual Desktop and LinkFT modules use a fixed pupil diameter rather than
measuring pupil dilation. The bridge cannot generate measurements the source
does not provide. LinkFT is described as experimental by its publisher.

AVATARS AND OUTPUT
Traditional VRCFaceTracking parameters, including Jerry's templates, are
supported when the avatar exposes them. Native VRChat face-tracking SDK beta
avatars use /tracking/face/v1 when their avatar tracking settings enable it.
The output mode follows the avatar's advertised support. An avatar still needs
the blendshapes and setup required to display the expressions it receives.

Default VRChat output is 127.0.0.1:9000 and avatar-change feedback is on
127.0.0.1:9001. OSCQuery can negotiate a local VRChat instance's actual port.
These are separate from each module's tracking-input port. Save connection
persists your connection edits; it does not install a module or change VRChat's
avatar setup. The send count records transmitted OSC messages, rather than
confirming that an avatar has visibly applied every value.

MODULE UPDATES AND SWITCHING
Import a new module ZIP to add or update a module. Select an installed module
to switch to it; the current worker stops before the new worker starts. The app
keeps installed releases available. A rejected package preserves the active
module, and a failed activation attempts to restore the previous worker.

Use ZIPs from publishers you trust. A module contains executable code and runs
with your Windows account's permissions. Format/API checks do not authenticate
the publisher. The separate worker enables clean restarts and is not a security
sandbox. Modules and headset software retain their own licenses. A future
breaking SDK or .NET change may require a bridge update as well.

YOUR FILES
Settings, imported module versions and activity logs are stored in:
  %LOCALAPPDATA%\BabbleFrameBridge
Existing VRCFaceTracking installations are not imported or modified. Logs stay
on your PC; the bridge does not initialize a telemetry sender. Closing the app
stops its tracking worker. Do not post logs containing avatar IDs, usernames,
network addresses or other private data without removing those details.

APPEARANCE
Light and dark modes automatically follow the Windows app color preference.
The original headset artwork and particle animation are included. Motion
respects Windows reduced-motion preferences and pauses while minimized.
IBM Plex Sans is included with its SIL Open Font License notice.

UPDATE OR REMOVE THE APP
Run a newer Babble Bridge installer over the existing app; close the app first.
Setup keeps the installation directory and your separate settings, logs and
module library. The first public 1.0.0 release also supports migration from the
retired private release series. Future releases use normal version ordering.
Uninstall through Windows Installed Apps. Normal uninstall removes app files
and shortcuts while preserving the separate AppData profile for a reinstall.
There is no configured online automatic-update service. App updates use setup
files, while module updates use ZIP imports inside the app.
