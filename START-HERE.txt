FACE TRACKING BRIDGE 1.3.0 — WINDOWS x64

PREREQUISITE
Install the Microsoft Visual C++ v14 Redistributable (x64) from Microsoft:
https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist
Setup does not download this prerequisite. The app includes its separate .NET
runtime and accompanying notices.

GET STARTED
1. Run FaceTracking-Bridge-Setup.exe. Setup installs for your Windows account and
   offers an optional desktop shortcut. For a portable build, extract the
   entire folder and keep its runtime, Assets, licenses and notice files.
2. Close the separate VRCFaceTracking app and open Face Tracking Bridge.
3. Open Modules and click Download next to your provider, or import your own
   VRCFaceTracking module DLL or ZIP. Modules come from their original authors and
   are never bundled. Choose Use module to start the selected profile.
   Each download adds only its requested profile: BFR uses module 4.0.0, while
   the dedicated Baballonia desktop download uses module 3.2.0.
4. Start the matching headset runtime or desktop tracking app. Enable the
   tracking permissions and forwarding settings it requires (see below).
5. Enable OSC in VRChat and select an avatar with face tracking. OSCQuery
   discovers a local VRChat instance and its avatar parameters automatically.
   Reselect the avatar if VRChat was already running and needs a refresh.

The selected module and its connection settings are remembered. Switching
modules restarts the tracking worker and applies the appropriate input.
Only one module is active at a time. Avoid running another tracking app that
uses the same input or VRChat output ports.

MODULE CONNECTIONS
Babble Headset Runtime
  Import the Baballonia VRCFaceTracking module and select its headset-runtime
  connection. Start Babble Frame Runtime on the headset. The headset and PC
  must be able to reach each other on the network. BFR Link uses UDP 6767.
  If Windows asks about network access, allow it on your trusted network as
  appropriate. This app does not install the headset runtime or edit firewall
  rules. If discovery is blocked, try the runtime's PC IP fallback.
  Module: https://github.com/Project-Babble/Baballonia/releases/tag/vrcft-module-4.0.0
  Runtime: https://github.com/Project-Babble/Babble-Frame-Runtime

Baballonia desktop
  Download Baballonia in Modules for the Expressions Alpha-compatible 3.2.0
  module, or import a compatible ZIP and select its desktop connection. An
  older 3.1.0 profile offers Update for Expressions Alpha inside Modules.
  Its older profile stays available to restore if an update cannot start. Keep the
  desktop Baballonia app running with VRCFaceTracking output enabled toward
  127.0.0.1:8888. Desktop input uses UDP 8888, including both eye and face input.
  Module: https://github.com/Project-Babble/Baballonia/releases/tag/vrcft-module-3.2.0
  App: https://github.com/Project-Babble/Baballonia

Virtual Desktop
  Import the VirtualDesktop.VRCFaceTracking module. Run Virtual Desktop
  Streamer 1.30 or later and enable eye/face tracking forwarding and the
  headset's required permissions. This module reads local shared memory;
  it does not use a tracking-input UDP port.
  Compiled ZIP: https://download.vrdesktop.net/files/VirtualDesktop.VRCFaceTracking.zip
  Source: https://github.com/guygodin/VirtualDesktop.VRCFaceTracking

Steam Link
  Import the Ykeara LinkFT module. In Steam Link advanced settings, enable OSC,
  share the available eye/face tracking data, and set OSC Output Port to 9015.
  This module receives local UDP on 127.0.0.1:9015.
  https://github.com/ykeara/LinkFT/releases/tag/1.0.6

Available expressions depend on your headset, module and avatar. The current
Virtual Desktop and LinkFT modules use a fixed pupil diameter rather than
measuring pupil dilation. The bridge cannot generate measurements the source
does not provide. LinkFT is described as experimental by its publisher.

AVATARS AND OUTPUT
Traditional VRCFaceTracking parameters, including Jerry's templates, are
supported when the avatar exposes them. Native VRChat face-tracking SDK beta
avatars use /tracking/face/v1 when their avatar tracking settings enable it.
The output mode follows the avatar's advertised support. An avatar still needs
the blendshapes and setup required to display the expressions it receives.

Default VRChat output is 127.0.0.1:9000 and avatar-change feedback is on
127.0.0.1:9001. OSCQuery can negotiate a local VRChat instance's actual port.
These are separate from each module's tracking-input port. Save connection
persists your connection edits; it does not install a module or change VRChat's
avatar setup. The send count records transmitted OSC messages, rather than
confirming that an avatar has visibly applied every value.

MODULE UPDATES AND SWITCHING
Import a new module ZIP to add or update a module. Select an installed module
to switch to it; the current worker stops before the new worker starts. The app
keeps installed releases available. A rejected package preserves the active
module, and a failed activation attempts to restore the previous worker.

Use ZIPs from publishers you trust. A module contains executable code and runs
with your Windows account's permissions. Format/API checks do not authenticate
the publisher. The separate worker enables clean restarts and is not a security
sandbox. Modules and headset software retain their own licenses. A future
breaking SDK or .NET change may require a bridge update as well.

YOUR FILES
Settings, imported module versions and activity logs are stored in:
  %LOCALAPPDATA%\BabbleFrameBridge
Existing VRCFaceTracking installations are not imported or modified. Logs stay
on your PC; the bridge does not initialize a telemetry sender. Quitting the app
stops its tracking worker. Do not post logs containing avatar IDs, usernames,
network addresses or other private data without removing those details.

STARTUP AND SYSTEM TRAY
Open Settings to enable Start with SteamVR, Close when SteamVR exits, or
Start minimized to system tray. These three options are off initially
and saves immediately. SteamVR startup needs an installed SteamVR runtime.
Changing its setting may briefly open SteamVR's background settings service;
it does not start a VR session. Auto-close waits until a SteamVR session has
actually been observed, then closes the app cleanly when that session ends.
Opening the bridge manually without SteamVR running leaves it open.
Clicking the window's X hides it in the system tray and keeps tracking running.
Double-click its tray icon to reopen, or right-click for Open and Quit. Opening
the app shortcut again also restores the existing window. Quit app in Settings
fully exits too. Start minimized applies on the next launch, including SteamVR
launches. Tracking starts even when the window opens directly in the tray.
If the Windows tray is unavailable, the window stays accessible instead.
Start the bridge when this app opens is also in Settings and controls whether
the saved module starts tracking. Close when SteamVR exits fully quits the app.
Upgrades refresh an enabled SteamVR registration to the installed path.
Uninstall removes this app's registration and clears that startup opt-in;
other saved preferences and imported modules stay available for a reinstall.

APPEARANCE
Light and dark modes automatically follow the Windows app color preference.
The original headset artwork and particle animation are included. Motion
respects Windows reduced-motion preferences and pauses while minimized.
IBM Plex Sans is included with its SIL Open Font License notice.
Tracking-connection particles move only while the bridge is running. Stopping
the bridge freezes their displayed positions and dims the background dots;
starting it brightens them and resumes motion when Windows allows animation.

RELAY, THE OPTIONAL HOLOGRAPHIC KITTY
Click the kitty face in the bottom-left sidebar to enable or hide Relay. The
choice is remembered. Wave your pointer near its face to excite it; gentle
clicks invite play and repeated pestering can make it grumpy. Relay may chase
and swat your cursor, give panels and buttons a visual wobble, get the zoomies,
groom, stretch, or recharge in a nap. It also sniffs, kneads, loafs, slow-blinks,
stalks, pounces, rubs against surfaces, and looks around. Play and rest unfold
in sequences; recent events, curiosity, trust, fatigue and habituation influence
what it does next. It can ignore a familiar cursor and attend to other things.
Its head, torso pieces, ears, paws and tail links use independent spring motion
and blended pose transitions for soft follow-through. Interrupted actions blend
smoothly into the next gesture instead of snapping to a new pose.
Relay is completely silent. Meows, chirps, yawns and purring appear only as small
text bubbles that fade away and do not intercept clicks. Audio playback and the
old sound option have been removed, including for profiles that enabled sound
in an earlier preview. Text reactions also work with reduced motion enabled.
The 35 behaviors are organized into interruptible hunting, settling, recovery,
grooming, exploration and play routines. New gestures include cautious peeking,
backing away, a pre-pounce wiggle, paw licking, face washing, ear flicks,
tail-chasing, flopping, dozing and a little startle response. Repetition,
frustration, willingness and recent activity help it choose a different plan.
The kitty never clicks controls, changes connection settings or moves your
system cursor. Only the cat itself intercepts clicks; the rest of the app stays
usable. Its renderer follows display refresh and pauses when disabled, hidden,
minimized or in the tray. Windows reduced-motion settings keep it still.
The original recurrent behavior model has 3,720 parameters and needs no model
download, network connection, account or external AI runtime. It was trained
on original synthetic behavior examples; mouse interactions are not recorded
or uploaded. The cat's original vector artwork and animations are included
under Apache 2.0. No VRChat mascot image or pretrained third-party model is
bundled. Its internal needs, memories and intentions are a software simulation.
See docs/RELAY-BEHAVIOR.md and tests/Kitty.Tests/README.md in the source for
behavior references and synthetic-training provenance.

UPDATE OR REMOVE THE APP
Run a Face Tracking Bridge installer over the existing app; first choose Quit
from the system tray menu or Settings. The window's X keeps the app running.
Setup keeps the installation directory and your separate settings, logs and
module library. The first public 1.0.0 release also supports migration from the
retired private release series. Future releases use normal version ordering.
Uninstall through Windows Installed Apps. Normal uninstall removes app files
and shortcuts while preserving the separate AppData profile for a reinstall.
There is no configured online automatic-update service. App updates use setup
files, while module updates use ZIP imports inside the app.

MODULE DOWNLOADS AND REMOVAL
Use the Modules page to download compiled ZIPs directly from their official
authors. Downloading adds a module to your library without stopping the active
bridge. Choose Use module to switch. You can still import a ZIP of your own.

The Headset Runtime / BFR choice uses Baballonia module 4.0.0 with BFR support;
the Baballonia desktop choice uses the separate Expressions Alpha-compatible
3.2.0 module package.
The headset runtime itself must be installed separately on the headset:
https://github.com/Project-Babble/Babble-Frame-Runtime/releases/latest

To remove an imported profile, click its red trash icon and confirm Remove.
Removing the selected profile stops the bridge and clears its selection.
Other modules, original downloaded ZIPs and VRChat connection settings stay.
Virtual Desktop's GitHub Source code ZIP is not a compiled module package.

OTHER SDK MODULES
You can import other compatible VRCFaceTracking SDK module DLLs or ZIPs.
module.json is optional. A bare DLL import copies only that file; if the module
needs supporting DLLs, native libraries or configuration files, place them
together in a ZIP. Ambiguous ZIPs need an optional manifest naming the entry DLL,
or you can import the entry DLL directly when it has no separate dependencies.
Custom modules manage their own inputs and ports. Follow their setup instructions.

VIRTUAL DESKTOP WAITING STATE
If the headset is not connected through Virtual Desktop, selecting its module
shows Waiting for Virtual Desktop. This is normal and does not mean the module
is broken. Start the Streamer, enable Forward tracking data to PC and connect
your headset; the selected worker connects automatically when the IPC is ready.
Installed provider downloads are hidden from Add a module. Removing a provider
profile makes its download available again; manual DLL/ZIP import stays available.

STARTUP RECOVERY
If connection settings are damaged, a valid saved backup is recovered and the
original damaged file is retained for inspection. Missing imported DLLs remain
listed as unavailable so other modules can still be used; restore, re-import or
remove the affected profile. Missing provider files make its download available
again. Unrecoverable startup errors show the recovery folder and close the app
instead of leaving an invisible instance running.
